# Gitunia review checklist

Read by the `reviewer` agent and by the implementer's self-review (via `.claude/workflow.md`, "Review checklist"). Gitunia-specific checks on top of the generic ones. Read only the rules files that match the diff.

1. **Scope.** Nothing beyond the Features and "Not included" lists in `README.md`.
2. **Git safety.** Destructive commands confirmed and undoable (reflog hint) where git allows; argument lists only, no shell string interpolation; no writes while only reading; `index.lock` contention handled; user config, hooks and credentials respected; no `GIT_*` env beyond `docs/git-layer.md`. Parsing edge cases: NUL separators, unicode, spaces, renames, detached/unborn HEAD, in-progress operations.
3. **Layering.** Git -> Core -> App -> Tui. Core is pure (no console or process), App has no Terminal.Gui reference, only Tui touches the console, Tui has no git logic. No blocking calls on the UI thread; every git call is async, cancellable, has a timeout and takes an explicit repo/worktree path (no static or global "current repo").
4. **Cross-platform.** No Linux-only APIs, paths or shell assumptions outside the platform abstraction; every platform branch covers all supported OSes or fails clearly; `Path` APIs, no hardcoded separators, `/dev/null` or `/tmp`.
5. **Native AOT.** No reflection, runtime codegen or non-AOT-safe packages; no new `IL*` warnings. Run the AOT publish if dependencies or serialization changed.
6. **UX.** Keyboard-only works; bindings are in `keymap.default.json` and the generated `docs/keymap.md` is current (`scripts/gen-keymap-doc.sh`) with no conflicts; destructive actions confirm; resize and tiny terminals don't crash; wide characters are never split. UI or shell-wiring changes get a smoke run of the real binary (`StartupSmokeTests` catches constructor-order crashes only).
7. **Performance.** Hot paths are listed in `docs/internal/performance.md` and the `performance` skill: claimed optimisations come with measured numbers; nothing materializes a whole large graph eagerly; allocation findings only on per-key or per-frame paths outside overlays and only with a measurement; streaming and virtualization where the docs call for them.
8. **Tests.** Risk areas in `docs/testing.md` covered by tests that fail if the code is wrong; real temp repos with isolated config; no network or wall-clock dependence. A new test class in `Gitunia.Core.Tests` or `Gitunia.Tui.Tests` that uses no file system, process, path, environment, terminal or real git carries `[Trait("Os", "Independent")]`; one that does must not (Windows CI skips marked classes, #637). Test names follow `Given<Context>_When<Action>_Then<Outcome>`. Don't ask for tests of `TuiApplication` or toolkit glue with no terminal-bound harness unless the logic could move into a testable type. Cover: empty/zero/tiny size, wide or combining characters, wrapped rows, several hunks, cancel and race, another tab or session active while an overlay is open; new caches, list sources, views and event wiring each get a test.
9. **Docs.** Docs sections describing behaviour the diff changes are updated (`docs/internal/ux*.md`, `git-layer.md`, `architecture.md`; grep changed identifiers, keys and labels; status hints, `ActionCatalog` titles, XML docs, test names). A `docs/internal/decisions.md` entry only for a non-obvious choice or an override (mark the superseded entry); never flag its absence for a change already documented in `ux*.md`.
10. **Style.** `.claude/rules/csharp-style.md` (type names, token last, tuples, interpolation, qualified names, capitalised comments, named constants for git format values, blank lines between steps and around multi-line statements, static readonly argument lists, folders and mirrored test folders, static vs instance, delegate dependencies and constructor size). `_field` naming is enforced by the build. For Git-layer or UI changes also `.claude/rules/git-layer.md` or `.claude/rules/ui-changes.md`. Checked by eye, only on lines the diff added. `scripts/inspect.sh --changed` after lambdas, events or `using`.
11. **Hygiene.** Conventional commits, no stray files, debug output or commented-out code.
12. **Destructive or ambiguous targets.** The confirm dialog names exactly what will be changed; a fallback never widens the scope (hunk to whole file, range to everything); texts that count things are pluralised and say what was not done on failure.

Reviewer: no `dotnet test` or build runs when the orchestrator says so; drop "unmeasured" performance findings for paths not listed in `docs/internal/performance.md`; constants, setters and extra edge-case tests are `nit`; end with the 2-3 things the owner should look at most closely if the change touches destructive git operations.
