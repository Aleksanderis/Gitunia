# Git layer: design history

How and why the decisions behind `docs/git-layer.md` were made, roughly in the order they were decided, with the measurements taken. Not required reading for ordinary work: the rules are in `.claude/rules/` and the current spec is in `docs/git-layer.md`. Where a later note contradicts an earlier one, the later one wins. Details of a fact in `docs/git-layer.md` that look out of date: check here and in the issue before changing code.

- Standalone launch (spike #3) findings for M1: resolve paths with `git -C <path> rev-parse`; check `--is-bare-repository` before `--show-toplevel`; a linked worktree has `--git-dir` != `--git-common-dir`; dedupe tabs by the resolved toplevel; a path inside a `.git` directory needs its own case. Resolving costs 0-2 ms.

- Commit ids are a fixed 40-byte `ObjectId` struct (SHA-1 or SHA-256) instead of interned hash strings (#13). Why: no intern table or string per parent link, equality and hashing without allocation. Cost: 40 bytes per id even for SHA-1 (about 12 bytes padding); per-commit memory is still dominated by `CommitInfo`, its subject string and decorations. Author names and emails are interned. The default log excludes `refs/stash` so stash commits do not appear as graph nodes; callers that pass revisions get exactly those.

- Diff parser (#15): `DiffParser` is incremental (feed byte chunks; a file is emitted when the next `diff --git` starts, so memory is bounded by the largest single file) and keeps every header and `@@` line verbatim, so `DiffPatchWriter.WriteFile` reproduces git's text exactly. `DiffReader` fixes the options that make output predictable (`--no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/ --find-renames --find-copies`); callers add the rest (`--cached`, `--binary`, `-U<n>`, `--format=` for `show`). Partial staging uses `DiffPatchWriter.WriteSelection` (hunk and line index addressing, counts and offsets recomputed; `Forward` to stage, `Reverse` to unstage or discard with `apply -R`). Known limits: combined diffs (`diff --cc`, merge commits) are skipped with a warning; invalid UTF-8 is replaced and a warning says the text is no longer exact, so such patches must not be applied; partial patches are not meaningful for binary, added or deleted files (stage whole) and hunks with zero context are not re-anchored; `GitRunner` has no stdin support, so applying a patch needs a temp file or a runner extension (follow-up for the staging issue).

- File watching (#27) lives in `Gitunia.Git` (no Core types): one `RepositoryWatcher` per tab, one shared `WatchBudget`, `RepositoryRefresher` for incremental refresh; details in the Refresh section above. The Platform abstraction is not involved: `FileSystemWatcher` is cross-platform and its failures (inotify limit, buffer overflow, unsupported file systems) fall back to polling, which is the per-OS escape hatch. Wiring into tab state and effects (calling `SetActive` on tab switch, running the refresh effect, applying the changed sections) is left to the UI work. Known limit: the recursive working tree watcher also sees `.git/objects`; the classifier filters those events but they still cost inotify watches.

- Commit details (#24; the debounce on every move and the FIFO cache described here were changed in #215, see "Faster commit details" in architecture.md): `CommitDetailsReader` (`Gitunia.Git`) runs `git log -1 -z` (parsed by `CommitDetailsParser`: full raw message, author and committer with their UTC offsets via `%aI`/`%cI`, parents) and then `git diff-tree --raw -z -M -C` against the explicitly named first parent (or `--root`), because `diff-tree` shows merges against every parent and ignores `--first-parent` (parsed by `CommitFileChangeParser`, statuses reuse `FileChangeKind`). In the Tui, `CommitDetailsStore` (one per tab, owned by `TabSession`) is fed by every graph selection change: it shows the loading state at once, debounces 80 ms, cancels the load of the previous selection (its git processes are killed), ignores stale results and caches the last 64 commits. Pane rows are width-independent (`DetailContentBuilder`; long lines are cut with an ellipsis, not wrapped) and drawn by `DetailPaneRenderer`, shared by the Terminal.Gui list source and `ScreenComposer`, so `--print-frame` shows the pane for the newest commit. Pane focus is `FocusedPane` of the tab's view state; `ActionRouter.ViewName` picks the keymap view (`Graph` or `Detail`) from it.

- Background status polling (#135): `StatusReader` takes an `UntrackedFilesMode`; `BackgroundStatusPoller` uses `Normal` (`--untracked-files=normal`: an untracked directory is one entry), because the tab bar only needs to know the tree is dirty. Measured on a throwaway repo with 20,000 untracked files in 100 directories: `all` 9 ms and 288 KB of output, `normal` 1 ms and 80 bytes (cold, large real trees will show a bigger gap). The active tab keeps `All`. `RepoStatusSummary.From(StatusSnapshot)` replaces the hand-built summaries (`TabRefresher` still builds its own, #144).
